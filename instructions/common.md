# Common Pi user policy

Use relevant native skills and project standards; do not turn a normal task into repeated installation or setup.

## Project context and private notes

Before a workflow needs tracker settings, personal tasks/specs/research or domain notes, run the project-context command named in the global AGENTS.md. Use inherited profiles and exceptions; read returned private instructions when present. Resolve the actual target project, not merely Pi's launch directory. Machine location, Git host and account login alone do not classify the task; use applicable private discovery instructions or clarify an unknown target before applying project-specific policy. Keep personal artifacts outside repositories. Read existing official repository documentation and respect its standards; alter official docs only when requested.

## Implementation and review

Record initial HEAD and pre-existing changes before editing. Keep unrelated changes and other sessions intact. Build the smallest real feedback loop, add a regression for a reproduced defect, and check the actual configured runtime rather than treating a handoff or package version as proof. Use TDD at agreed seams.

Before a proposed commit, independently review Standards and Spec, including task-owned staged, unstaged and new files against the recorded base. Freeze the reviewed scope, collect both reports, fix findings and repeat affected validation. With no requested commit, leave tested changes uncommitted.

## Publication

A request to implement, fix, test, review, install or update is not permission to commit or publish. Ask for explicit task authorization before commits, push, PR/MR creation, repository publication, or remote issue/label changes. Never run automatic commits inherited from a third-party skill.

Preserve accepted behavior when integrating upstream. Prefer additive topic branches and a combined installation branch; preserve published history. Report what is local, pushed, merged, installed and only tested offline separately.

## Privacy and machines

Common public configuration contains no credentials, private tracker addresses, chat allowlists, corporate instructions, browser profiles or conversation history. Home and work share mechanics, not all instructions. Machine-private policy remains private and is preserved on updates. Each computer gets its own login and environment.
