# Рабочий ноутбук

Это переносимые личные инструкции для работы у любого работодателя,
а не конфигурация конкретной компании. Дома этот каталог не устанавливается.

Если рабочие проекты живут в GitLab, а личные в GitHub, см. [настройку Git на одном Mac](git.md). Она не зависит от установки рабочего `AGENTS.md`.

## Установка дополнения

Сначала установи общую конфигурацию по инструкции для
[Windows](../windows/README.md) или [macOS](../macos/README.md).
Затем **из корня checkout** отдельно скопируй рабочий `AGENTS.md`.
Если целевой файл уже существует, команды останавливаются: сравни файлы
и перенеси нужные правила вручную, не затирая свои инструкции.

### Windows / PowerShell 7

```powershell
$target = Join-Path $HOME '.pi/agent/AGENTS.md'
if (Test-Path -LiteralPath $target) {
    throw "Уже существует $target. Сравни файлы и объедини правила вручную."
}
Copy-Item -LiteralPath './work/agent/AGENTS.md' -Destination $target -ErrorAction Stop
```

### macOS

```sh
(
  target="$HOME/.pi/agent/AGENTS.md"
  if [ -e "$target" ] || [ -L "$target" ]; then
    printf '%s\n' "Уже существует $target. Сравни файлы и объедини правила вручную." >&2
    exit 1
  fi
  cp ./work/agent/AGENTS.md "$target"
)
```

В **установленном локальном** `~/.pi/agent/AGENTS.md` замени все
`<WORK_REPOS>` абсолютным путём к рабочим репозиториям на этой машине.
Уточни ссылки на `AGENTS.md`, `MAP.md` и `dev-rules/README.md`, если на новом
месте они называются иначе; эти справочники не требуется создавать ради Pi.
Реальные пути и корпоративные сведения обратно в этот репозиторий не переноси.

Перезапусти Pi или выполни `/reload`. Если в каталоге агента есть
`AGENTS.override.md`, он заменяет соседний `AGENTS.md`: проверь, какие инструкции
действительно загружаются.

## Что сохраняет рабочий файл

- Полномочия: внешние изменения, коммиты, push и теги — только по явному поручению;
  наличие доступа и делегирование не расширяют разрешения.
- Навигацию: Pi может запускаться вне репозитория; рабочие инструкции, карта
  репозиториев и справочные рекомендации помогают найти нужный контекст,
  но не навязывают обязательный процесс.
- Границу применимости: рабочая навигация относится к задачам работодателя,
  а не к личным проектам на том же ноутбуке. Общие ограничения полномочий
  продолжают действовать.

Корневой [`AGENTS.md`](../AGENTS.md) этого репозитория описывает обслуживание
`pi-config`. Его не нужно копировать в каталог агента.

## Что остаётся только локально

MCP-сервисы и авторизация работодателя, корпоративные skills, карты репозиториев,
справочники и внутренние правила добавляются отдельно. Правила конкретных
проектов размещай на соответствующем уровне каталогов, не распространяя их
случайно на личные проекты. Закрытые материалы и учётные данные не публикуются.

Перед подключением сторонних skills полезно разобрать их через `skill-creator`:
проверить инструменты, shell, зависимости и навязанные настройки, действия или
workflow. Совместимость с Pi адаптируется отдельно от изменения методики;
спорные требования согласовываются, а не удаляются автоматически.

Общий `collaborative-dev` уже устанавливается вместе с `agent/*` и пригоден
как дома, так и на работе. Включай его явно через `/skill:collaborative-dev`;
он не активируется автоматически.
