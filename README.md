# pi-config

Личный набор конфигурации Pi для Windows и macOS / Apple Silicon. После копирования файлов checkout не нужен работающему Pi.

## Состав

| Источник | Куда устанавливается |
| --- | --- |
| `agent/*` | `~/.pi/agent/` |
| `agent/skills/skill-creator/` (входит в `agent/*`) | `~/.pi/agent/skills/skill-creator/` |
| `billion-context/billion-context.json` | `~/.config/billion-context/billion-context.json` |
| `windows/README.md`, `macos/README.md` | Инструкции первоначальной настройки, не файлы runtime |

Здесь `~` — домашний каталог пользователя: обычно `C:\Users\<имя>` на Windows и `/Users/<имя>` на macOS. Названия каталогов Pi и Bili одинаковые на обеих ОС; в общей таблице используется запись с `/`, а команды Windows ниже используют PowerShell-пути.

Конфиги общие. Отличие инструментов: Windows добавляет `-bash,+powershell`; macOS использует штатный Bash. Интерактивный Zsh на Mac менять не нужно. Внешний конфиг Billion Context учитывает `XDG_CONFIG_HOME`, если он задан.

Семь расширений перечислены только в `agent/settings.json`: поиск, собственный compact-transcript, goal, loop, smart-fetch, Billion Context и subagent. Источники без фиксации версий. У goal отключены поставляемые prompts, у loop — skills. Собственный compact не спрашивает о настройках и не требует `compact-transcript.json`.

Сохранены личные предпочтения интерфейса, основная модель Sol, `xhigh` и четыре override контекста 272000. Три универсальных агента `light/standart/strong` используют Luna/Terra/Sol и наследуют инструменты; модели указаны в их файлах. `enabledModels` ограничивает переключение основной модели, не выбор модели агента.

## Первоначальная установка

1. Нужны Pi, Node.js с `npm/npx` и Git; для Windows также PowerShell 7. Node для npm-версии Pi — не ниже 22.19.0. Редактор `code --wait` нужен только для вызова внешнего редактора: установи команду VS Code в PATH либо измени `externalEditor`.
2. Клонируй `https://github.com/mishkidreams/pi-config.git` (или распакуй скачанный архив) и перейди в корень checkout. Выполни короткую инструкцию для [Windows](windows/README.md) или [macOS](macos/README.md). Она копирует общие файлы и **однократно сохраняет** ограничение вложенности.
3. Если HTTP-прокси нужен для доступа или ты хочешь использовать его по своему выбору, сначала выполни раздел прокси своей ОС и [настрой Bili](#прокси-и-vpn). Затем запусти `pi`. Недостающие пакеты из settings устанавливаются штатно; первый запуск требует сети. Ошибку установки не игнорируй: повторить установку/обновление расширений можно через `pi update --extensions`.
4. Через `/login` авторизуй `openai-codex`. Нужен аккаунт с доступом к указанным моделям. Авторизация создаётся на этой машине, в репозитории её нет.
5. Для Browser MCP установи [расширение Chrome](https://browsermcp.io/install) в обычный рабочий профиль. При первом обращении выполни сопряжение и разреши доступ; следующие подключения используют сохранённую локальную идентичность. Не добавляй вторую копию MCP в настройки.
6. Context7 использует публичный HTTPS endpoint. Если сервис запросит авторизацию или ограничит доступ, это отдельное условие сервиса; репозиторий не предоставляет учётные данные.

Инструкции рассчитаны на пустой профиль, не на перезапись уже настроенного Pi. Старую конфигурацию сначала сохрани отдельно.

## Дополнительно для рабочего компьютера

При необходимости добавь отдельный локальный корпоративный слой:

- MCP-сервисы и их авторизацию, корпоративные skills;
- `AGENTS.md` с нужными правилами работы с ветками, окружениями и другими ресурсами; размещай его на уровне, где эти правила должны действовать, не распространяя их случайно на личные проекты;
- ссылку из этих инструкций на `MAP.md` с картой репозиториев, если такая навигация полезна.

Перед подключением сторонних skills полезно разобрать их через `skill-creator`: проверить инструменты, shell, зависимости и навязанные настройки, действия или workflow. Совместимость с Pi адаптируется отдельно от изменения методики; спорные требования согласовываются, а не удаляются автоматически. Закрытые материалы и учётные данные в этот репозиторий не копируются.

## Проверка после установки

- `pi mcp list --json`: в базовом наборе `browsermcp` и `context7`, оба `direct`, без ошибок подключения. Локально добавленные корпоративные сервисы могут расширять этот список.
- В Pi доступен `/skill:skill-creator`; каталог субагентов содержит `light`, `standart`, `strong`.
- Спроси агента о доступных инструментах: Windows — `powershell` без `bash`, macOS — `bash` без принудительного PowerShell.
- В новом терминале проверь сохранённое `PI_SUBAGENT_MAX_DEPTH=1` по инструкции своей ОС. Основной агент может делегировать, дочерние не получают инструмент `subagent`. Это не ограничение количества параллельных детей и не OS sandbox.
- После авторизации можно выполнить короткий запрос к модели; для реальной проверки браузера нужен открытый Chrome и завершённое сопряжение.

## Прокси и VPN

HTTP-прокси нужен не в каждой сети, но его можно использовать и по своему выбору. Если провайдеры доступны напрямую или через настроенный системный/корпоративный VPN и ты не планируешь использовать HTTP-прокси, этот раздел можно пропустить. Само наличие VPN ещё не гарантирует доступ: важен реальный маршрут до провайдера.

Если HTTP-прокси нужен для доступа или ты хочешь использовать его по своему выбору, нужны две настройки:

1. Переменные `HTTP_PROXY`, `HTTPS_PROXY` и исключения `NO_PROXY` по инструкции ОС — для Pi без расширений и других программ, поддерживающих эти переменные.
2. В **локальном** `~/.config/billion-context/billion-context.json` (либо под `XDG_CONFIG_HOME`) добавь поле `"proxy": "http://HOST:PORT"`, заменив `HOST:PORT` действительным адресом того же HTTP-прокси. Сохрани остальные поля, включая `pi.subagents` и `upstreamProxyMode`.

Это не лишнее дублирование: при нативном запуске отдельного процесса Bili обычные proxy-переменные могут быть удалены из его окружения. Поэтому одного `upstreamProxyMode: auto` недостаточно как гарантии маршрута через выбранный HTTP-прокси; явный `proxy` переживает этот путь запуска. Речь об исходящем прокси Bili до провайдера, а не о локальном адресе самого Bili.

Общий JSON не содержит адреса машины. Если используешь HTTP-прокси, выполни локальную настройку выше. Используй HTTP/CONNECT endpoint, не SOCKS. Не сохраняй `HOST:PORT` буквально и не добавляй пустой `proxy` вместо адреса. После изменения окружения открой новый терминал и перезапусти Pi; уже работающий процесс Bili может сохранять прежние настройки.

## Что не переносится

Auth, MCP-токены, сессии, cookies, browser profiles, device ID и отметки просмотренных changelog создаются локально. Здесь нет глобального AGENTS, закрытых корпоративных материалов, Telegram MCP, генераторов или ссылок на лабораторный репозиторий. LICENSE рядом со skill — уведомление о лицензии, не инструкция агенту.

Windows-инструкции проверены исполнением в изолированном профиле; macOS-скрипты — статически, без настоящего macOS/ARM64 runtime-теста. У Browser MCP ранее наблюдались отдельные 5-секундные таймауты screenshot; успешное подключение не означает, что эта особенность исправлена.
