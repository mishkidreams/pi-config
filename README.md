# pi-config

Личный набор конфигурации Pi для Windows и macOS / Apple Silicon. После копирования файлов checkout не нужен работающему Pi.

## Дома и на работе

- **Дома:** общая конфигурация из `agent/` и `billion-context/` плюс инструкция своей ОС. Рабочий `AGENTS.md` не устанавливается.
- **На рабочем ноутбуке:** та же общая конфигурация плюс [отдельный шаг из `work/`](work/README.md). Он устанавливает полный обезличенный `AGENTS.md` с правилами полномочий и рабочей навигацией.
- **Данные конкретного работодателя:** MCP, авторизация, внутренние инструкции и материалы добавляются только локально и не входят в репозиторий.

`windows/` и `macos/` разделяют особенности ОС, а не домашнее и рабочее использование. Общие настройки не дублируются.

## Состав

| Источник | Куда устанавливается |
| --- | --- |
| `agent/*` | `~/.pi/agent/` |
| `agent/system-prompts/` (входит в `agent/*`) | `~/.pi/agent/system-prompts/` |
| `agent/skills/skill-creator/` (входит в `agent/*`) | `~/.pi/agent/skills/skill-creator/` |
| `agent/skills/rules-creator/` (входит в `agent/*`) | `~/.pi/agent/skills/rules-creator/` |
| `agent/skills/collaborative-dev/` (входит в `agent/*`) | `~/.pi/agent/skills/collaborative-dev/` |
| `agent/skills/retro/` (входит в `agent/*`) | `~/.pi/agent/skills/retro/` |
| `billion-context/billion-context.json` | `~/.config/billion-context/billion-context.json` |
| `work/agent/AGENTS.md` (только отдельным рабочим шагом) | `~/.pi/agent/AGENTS.md` |
| `windows/README.md`, `macos/README.md`, `work/README.md` | Инструкции первоначальной настройки, не файлы runtime |

Здесь `~` — домашний каталог пользователя: обычно `C:\Users\<имя>` на Windows и `/Users/<имя>` на macOS. Названия каталогов Pi и Bili одинаковые на обеих ОС; в общей таблице используется запись с `/`, а команды Windows ниже используют PowerShell-пути.

Конфиги общие. Отличие инструментов: Windows добавляет `-bash,+powershell`; macOS использует штатный Bash. Интерактивный Zsh на Mac менять не нужно. Внешний конфиг Billion Context учитывает `XDG_CONFIG_HOME`, если он задан.

Общие расширения в `agent/settings.json` — поиск, собственный compact-transcript, goal, loop, smart-fetch, Billion Context, subagent, pi-prompt-profiles, `@gowthamgts/pi-codex-fast-mode`, `pi-think-twice` и `@yukikisaku/pi-retain-cache`. Источники без фиксации версий. У goal отключены поставляемые prompts, у loop — skills. Собственный compact не спрашивает о настройках и не требует `compact-transcript.json`.

При наборе обычного промпта `Enter` запускает трёхсекундный отсчёт до отправки. Если продолжить печатать или нажать `Esc`, отправка отменится, а текст останется в редакторе. Чтобы отправить раньше, нажми `Enter` ещё раз не менее чем через секунду после первого нажатия. [pi-think-twice на npm](https://www.npmjs.com/package/pi-think-twice).

Основная модель — `openai/gpt-6.2-astra`; в переключателе также доступна `openai/gpt-6.2-sol`. Уровень рассуждений по умолчанию — `max` для основной модели и всех трёх субагентов. Размеры контекстных окон берутся из каталога Pi без локальных переопределений.

Субагенты используют того же провайдера: `light` — `gpt-6-luna`, `standart` — `gpt-6.1-terra`, `strong` — `gpt-6.2-sol`. Их модели заданы в `agent/agents/` независимо от `enabledModels`; инструменты они наследуют.

Fast включён по умолчанию. Расширение запрашивает `service_tier: "priority"` для любой модели через Responses API провайдеров `openai` и `openai-codex`, не меняя уровень рассуждений. Отдельный список моделей не нужен. Ultrafast расширение не запрашивает. `/fast off` и `/fast on` сохраняют выбор для новых сессий, в том числе субагентов. `/fast status` показывает текущую настройку. [Описание расширения](https://github.com/gowthamgts/pi-stuff/tree/main/extensions/codex-fast-mode).

При входе через ChatGPT расход включённой квоты в режиме Fast относительно Standard составляет 2× для GPT-6.2 Astra и Sol и 2,5× для GPT-6.1 Terra и GPT-6 Luna. Для новых моделей доступность и коэффициенты определяет OpenAI. [Тарифы Fast](https://learn.chatgpt.com/docs/pricing#speed-multipliers).

### Прогрев кэша GPT во время простоя

Пока Pi открыт в терминале и компьютер не спит, `@yukikisaku/pi-retain-cache` отправляет в ту же сессию короткие скрытые запросы, чтобы при возвращении к работе модель могла повторно использовать кэш промпта. Для GPT по умолчанию запросы идут раз в 25 минут и прекращаются через 2 часа после последнего обычного ответа. Они расходуют квоту подписки ChatGPT и не гарантируют попадания в кэш.

В меню `/retain-cache` можно изменить интервал (`gpt interval`), предел простоя (`Retain prompt cache for`) и уведомления о промахах кэша. Стрелки ↑/↓ выбирают строку, ←/→ меняют значение. В новый профиль расширение устанавливается с общей конфигурацией. В существующий его можно добавить отдельно командой `pi install npm:@yukikisaku/pi-retain-cache`, затем выполнить `/reload` в открытом Pi. [pi-retain-cache на GitHub](https://github.com/yukikisaku/pi-retain-cache).

## Первоначальная установка

1. Нужны Pi, Node.js с `npm/npx` и Git; для Windows также PowerShell 7. Node для npm-версии Pi — не ниже 22.19.0. Редактор `code --wait` нужен только для вызова внешнего редактора: установи команду VS Code в PATH либо измени `externalEditor`.
2. Клонируй `https://github.com/mishkidreams/pi-config.git` (или распакуй скачанный архив) и перейди в корень checkout. Выполни короткую инструкцию для [Windows](windows/README.md) или [macOS](macos/README.md). Она копирует общие файлы и **однократно сохраняет** ограничение вложенности. На рабочем ноутбуке затем отдельно установи [рабочее дополнение](work/README.md); дома этот шаг пропускается.
3. Если HTTP-прокси нужен для доступа или ты хочешь использовать его по своему выбору, сначала выполни раздел прокси своей ОС и [настрой Bili](#прокси-и-vpn). Затем запусти `pi`. Недостающие пакеты из settings устанавливаются штатно; первый запуск требует сети. Ошибку установки не игнорируй: повторить установку/обновление расширений можно через `pi update --extensions`.
4. Для работы по подписке ChatGPT войди через `/login openai`. Если вместо входа через ChatGPT использовать `OPENAI_API_KEY`, запросы оплачиваются по тарифам API. Учётные данные остаются на машине и не входят в репозиторий.
5. Для Browser MCP установи [расширение из Chrome Web Store](https://chromewebstore.google.com/detail/browser-mcp-let-ai-use-yo/bjfgambnhccakkhmkepdoekmckoijdlc) в обычный рабочий профиль. При первом обращении выполни сопряжение и разреши доступ; следующие подключения используют сохранённую локальную идентичность. Не добавляй вторую копию MCP в настройки.
6. Context7 использует публичный HTTPS endpoint. Если сервис запросит авторизацию или ограничит доступ, это отдельное условие сервиса; репозиторий не предоставляет учётные данные.

Команды копирования рассчитаны на пустой профиль. Если Pi уже запускался, сохрани старую конфигурацию отдельно и объедини настройки. Оставь `deviceId` и `lastChangelogVersion` из локального `settings.json`, если они есть. С другой машины эти поля не переноси.

## Дополнительно для рабочего компьютера

Если на одном Mac используешь рабочий GitLab и личный GitHub, настрой [два профиля Git по адресу репозитория](work/git.md). Инструкция включает вход по SSH и через `gh`, а также проверку без коммита и пуша.

В [work/README.md](work/README.md) описаны установка рабочего `AGENTS.md`, локальная подстановка корня репозиториев и подключение материалов нового работодателя. Рабочий файл сохраняет оба раздела — полномочия и навигацию — без названий компаний и пользовательских путей. Закрытые материалы и учётные данные в этот репозиторий не копируются.

## Общий системный профиль

[`pi-prompt-profiles`](https://pi.dev/packages/pi-prompt-profiles) добавляет в системный промпт основного агента и субагентов [личные правила](agent/system-prompts/profiles/personal.md) и унаследованный [адаптированный текст Codex](agent/system-prompts/profiles/codex.md). Pi сохраняет свою роль, инструменты, `AGENTS.md` и каталог навыков. На чистую машину оба файла и настройка профиля копируются с `agent/*`, расширение — из `agent/settings.json`; ничего отдельно из Codex скачивать не нужно. [Как отключить и вернуть профиль](agent/system-prompts/README.md#как-отключить-и-вернуть-профиль) · [Источник и порядок обновления](agent/system-prompts/README.md).

## Работа над правилами

[`rules-creator`](agent/skills/rules-creator/SKILL.md) доступен модели при создании, адаптации и аудите инструкций. Например: `/skill:rules-creator проверь, совместим ли предлагаемый промпт с рабочим AGENTS.md и навыком публикации`. Он разбирает, какие правила встретятся в одной задаче, предупреждает о конкретных противоречиях и предлагает, где их исправить. Это не фоновая проверка каждой сессии. Для авторства самого `SKILL.md` остаётся `skill-creator`.

## Совместная разработка

`collaborative-dev` — общий для дома и работы навык осмысленных итераций с промежуточным ревью, учётом будущих зависимостей и самостоятельностью в согласованных границах. Он сохраняет личный режим взаимодействия, а не вводит обязательный процесс для всех задач.

Вызов: `/skill:collaborative-dev`. В навыке сохранено `disable-model-invocation: true`: он не попадает в автоматический каталог модели, но доступен по явной команде. Для субагентов отдельно оговорено выполнение поручения родителя, без ожидания пользовательского ревью.

## Ретроспектива

`/skill:retro` разбирает текущую сессию, а по запросу — другую сессию или отдельную итерацию. Его можно вызвать и по ходу работы: `/skill:retro почему пришлось дважды переделывать проверку?` Навык предлагает в чате, что сохранить, упростить или исправить в окружении Pi. Он не ведёт отдельный журнал; ты выбираешь, что применить.

Это самостоятельная адаптация [retro Мэтта Покока](https://github.com/mattpocock/skills/blob/5863806dd4e15c63174bee4e7515a4256792ecfa/skills/engineering/retro/SKILL.md) для Pi ([MIT](agent/skills/retro/LICENSE)).

## Проверка после установки

- `pi mcp list --json`: в базовом наборе `browsermcp` и `context7`, оба `direct`, без ошибок подключения. Локально добавленные корпоративные сервисы могут расширять этот список.
- После установки `skill-creator` и `rules-creator` видны модели и доступны как `/skill:skill-creator` и `/skill:rules-creator`. Ещё два навыка вызываются только явно: `/skill:collaborative-dev` и `/skill:retro`. Каталог субагентов содержит `light`, `standart`, `strong`.
- Для проверки первой установки запусти `pi` из нового терминала, не возобновляя старую сессию. `/sp status` должен показать глобальный профиль `codex`. После изменения только файлов профиля достаточно `/sp reload`.
- После рабочего шага проверь локальный `~/.pi/agent/AGENTS.md`: оба раздела сохранены, `<WORK_REPOS>` заменён реальным путём. Базовая домашняя установка этот файл не создаёт; ранее существующий файл она также не удаляет.
- Спроси агента о доступных инструментах: Windows — `powershell` без `bash`, macOS — `bash` без принудительного PowerShell.
- В новом терминале проверь сохранённое `PI_SUBAGENT_MAX_DEPTH=1` по инструкции своей ОС. Основной агент может делегировать, дочерние не получают инструмент `subagent`. Это не ограничение количества параллельных детей и не OS sandbox.
- После авторизации можно выполнить короткий запрос к модели; для реальной проверки браузера нужен открытый Chrome и завершённое сопряжение.

## Прокси и VPN

HTTP-прокси нужен не в каждой сети, но его можно использовать и по своему выбору. Если провайдеры доступны напрямую или через настроенный системный/корпоративный VPN и ты не планируешь использовать HTTP-прокси, этот раздел можно пропустить. Само наличие VPN ещё не гарантирует доступ: важен реальный маршрут до провайдера.

Если HTTP-прокси нужен для доступа или ты хочешь использовать его по своему выбору, нужны две настройки:

1. Переменные `HTTP_PROXY`, `HTTPS_PROXY` и исключения `NO_PROXY` по инструкции ОС — для Pi без расширений и других программ, поддерживающих эти переменные.
2. В **локальном** `~/.config/billion-context/billion-context.json` (либо под `XDG_CONFIG_HOME`) добавь поле `"proxy": "http://HOST:PORT"`, заменив `HOST:PORT` действительным адресом того же HTTP-прокси. Сохрани остальные поля, включая `pi.subagents` и `upstreamProxyMode`.

Это не лишнее дублирование: при нативном запуске отдельного процесса Bili обычные proxy-переменные могут быть удалены из его окружения. Поэтому одного `upstreamProxyMode: auto` недостаточно как гарантии маршрута через выбранный HTTP-прокси; явный `proxy` переживает этот путь запуска. Речь об исходящем прокси Bili до провайдера, а не о локальном адресе самого Bili.

Общий JSON не содержит адреса машины. Если используешь HTTP-прокси, выполни локальную настройку выше. Используй HTTP/CONNECT endpoint, не SOCKS. Не сохраняй `HOST:PORT` буквально и не добавляй пустой `proxy` вместо адреса. После изменения окружения открой новый терминал и перезапусти Pi; уже работающий процесс Bili может сохранять прежние настройки.

## Что не переносится

Auth, MCP-токены, сессии, cookies, browser profiles, device ID и отметки просмотренных changelog создаются локально. Глобальный AGENTS поставляется только как отдельно устанавливаемый обезличенный рабочий шаблон в `work/agent/AGENTS.md`; в базовом `agent/` его нет. Здесь нет закрытых корпоративных материалов, Telegram MCP, генераторов или ссылок на лабораторный репозиторий. LICENSE рядом со skill — уведомление о лицензии, не инструкция агенту.

Windows-инструкции проверены в изолированном профиле. На macOS / Apple Silicon проверены базовый профиль `codex`, вызов субагента, запрос к Context7 и чтение страницы в Chrome через Browser MCP. Установка отдельного рабочего `AGENTS.md` на этом Mac в проверку не входила. У Browser MCP ранее наблюдались отдельные 5-секундные таймауты screenshot; успешное подключение не означает, что эта особенность исправлена.
