# Личные правила и профиль Codex для Pi

По умолчанию основной агент и субагенты используют `global:personal`. В [настройках](config.json) он наследует `global:codex` через `extends`. В системный промпт попадают сначала [личные правила](profiles/personal.md), затем [адаптация Codex](profiles/codex.md) и штатные инструкции Pi. Их модели, инструменты, рабочие каталоги и инструкции по-прежнему задаёт Pi. Для работы не нужны установленный Codex CLI, сеть для загрузки промпта или этот checkout.

**Источник адаптации Codex:** стабильный релиз OpenAI Codex CLI [`rust-v0.170.0`](https://github.com/openai/codex/releases/tag/rust-v0.170.0), ревизия [`29eb79e9866b`](https://github.com/openai/codex/commit/29eb79e9866b3262a777fdf8195c1b9e63684c91). В [каталоге релиза](https://github.com/openai/codex/blob/29eb79e9866b3262a777fdf8195c1b9e63684c91/codex-rs/models-manager/models.json) взят `model_messages.instructions_template` для `gpt-6.2-astra`; у `gpt-6.2-sol` он идентичен. Это опубликованный шаблон CLI, а не весь промпт сервиса OpenAI. Изменённый текст распространяется с исходными [лицензией Apache-2.0](upstream/codex/LICENSE) и [NOTICE](upstream/codex/NOTICE).

## Что перенесено и что отличается

Сохранены характер и стиль общения, промежуточные обновления и самодостаточный финал, самостоятельность, критерии готовности, работа с исправлениями и уточнениями, все семь рекомендаций по коду, фронтенд-дизайн (включая список шрифтов), форматирование и визуализации. Важная недоделка или непроверенная сборка должна попасть в финальный ответ, даже если об этом уже говорилось в чате.

- Роль задаёт Pi. Самоназвание «You are Codex», конкретная модель, чужие имена инструментов, каталог плагинов и синтаксис вызовов не перенесены. Поиск, параллельное чтение, экранирование, выбор навыков и обращение к сервисам описаны как переносимые принципы.
- Самостоятельность действует **в пределах поручения**. Пример Codex с автоматическим созданием чернового PR не даёт разрешения на внешнюю запись. Согласованное ревью остаётся точкой остановки, а субагент возвращает результат родителю. О реальном конфликте действующих инструкций агент сообщает пользователю.
- Предпочтения стиля не запрещают сообщать, чего не хватило, и не ломают требуемый формат. Вопросы, ожидание, сжатие контекста, пути к файлам и визуализации учитывают возможности текущего интерфейса; у пользователя не предполагается конкретный клиент Codex.

## Как отключить и вернуть профиль

Команды ниже отключают оба слоя. Если в текущей сессии нужен только Codex без личных правил, выбери `/sp use global:codex`.

| Где | Отключить | Вернуть профиль по умолчанию |
| --- | --- | --- |
| Только в текущей сессии | `/sp off` | `/sp auto` |
| По умолчанию на этой машине, включая новые сессии и новых субагентов | `/sp set selection off --scope global` | `/sp unset selection --scope global` |

Для разового запуска без профиля есть также `pi --sp-off`. Команда `/sp off` в родительском чате не выключает профиль у отдельно запущенного субагента с новой сессией. Глобальная команда меняет `~/.pi/agent/system-prompts/config.json` на этой машине, сохраняя `defaultProfile` и файлы профилей. Явный выбор в сессии или настройка `selection` доверенного проекта имеет приоритет над глобальной.

Проверить результат можно через `/sp status`: при отключении будет `mode: off`, после возврата к общему профилю — `profile: global:personal`. Чтобы другой уже открытый чат перечитал глобальную настройку, используй `/sp reload`; если в нём уже был явный выбор, переключи его отдельно или начни новую сессию.

## Обновление

Раз в месяц-два или по необходимости открой [последний стабильный релиз](https://github.com/openai/codex/releases/latest) и найди полный шаблон актуальной флагманской модели. Сравни его с шаблоном **указанной выше ревизии**. Через `rules-creator` пересмотри изменения по смыслу, включая актуальные `AGENTS.md`, инструменты, навыки и правила субагентов. Порядок моделей в каталоге и номера строк не определяют, что переносить. Обнови профиль и ссылку на ревизию вместе, затем перенеси проверенную копию на нужные машины. Обновление npm-пакета само текст профиля не меняет.

`/sp status` показывает выбранный профиль; `/sp reload` перечитывает его файлы. После установки самого расширения в открытом Pi нужен `/reload` или новый процесс. При изменении способа доставки проверь не только превью: в исходящем запросе родителя и дочернего процесса личные правила и текст Codex должны присутствовать по одному разу вместе со штатными инструкциями и объявлениями инструментов Pi.
